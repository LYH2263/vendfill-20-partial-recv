# VendFill 售货机补货

按货道容量、库存与在途量计算缺口，生成不超缺口、非负的补货单；支持分批到货、按行部分核销。

技术栈：Python 3.12 / FastAPI / SQLAlchemy / PostgreSQL / Vue 3 / TypeScript / Vite

## 分批核销规则（行状态 / 货道 / 整单 / 汇总同一套原子规则）

- 开单（`POST /api/refills/run`，进行中单据幂等复用）：正补量行立即**预占在途**口径。
- 行有两个核销态：`pending`（待核销，补量继续占用在途）与 `verified`（已核销：按补量加库存、扣在途）；零补量行（满仓/超占）不参与核销。
- `POST /api/refills/{id}/verify` 传入选中的 `lane_ids` 即可**分批部分核销**：
  - 入选行：加库存、扣在途；未选中行保持待核销、继续占用在途。
  - 整单仅在**全部正补量行都已核销**时才置 `completed`，不会出现「整单已完成但仍有待核销行」。
  - 任一行核销失败（已核销、补量 0、在途不足、整单已完成/已作废）→ **本批全部回滚**，未选中行与货道、汇总回到批前。
  - 已完成整单再核任何行一律 `409` 拒绝。
- `POST /api/refills/{id}/void` 作废整单：释放全部待核销行的在途占用（已核销库存不动），之后禁止核销。

```bash
docker compose up --build
```

## 使用说明

1. 在「点位」「货道」查看售货机布局与实时库存/在途。
2. 打开「补货小票」，首次进入自动开单（在途按补量预占）。
3. 货到一批就在小票上**勾选到货行 → 核销勾选**；行状态、右侧货道实时口径、「汇总」同步更新。
4. 全部正补量行核销后整单自动完成；无法到货时可「作废整单」释放在途。
5. 在「满仓」「汇总」查看已满货道、核销进度与补货合计。

### 种子示例

初始点位中 A1 缺 15、B1 缺 7（库存在途 3/2）、C1 缺 10。先核销 B1：B1 库存 3→10、在途 9→2，A1/C1 仍待核销且在途仍按补量占用，整单进行中；再核销 A1、C1 后整单完成，汇总与货道一致。
